# 03: 增量同步——变更探测

**What to build:** 改一个笔记再点同步，只有它被传上去；在别处（另一台机器、NAS 的文件管理器）改了远端的另一个笔记，同步时只有它被拉下来。没变的文件不重复传输。远端那一侧的判定靠验证符、修改时间与大小三者**任一不同**就下载并算内容 hash 确认——**内容 hash 才是权威，验证符只做变化探测**。

规格依据：决议 20–21、35、48–49。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 本地修改 → 只有该文件被上传
- [ ] 远端修改 → 只有该文件被下载
- [ ] 未变更的文件不产生传输
- [ ] 远端验证符变了但内容没变时：下载确认后内容 hash 相同，只更新状态表记录，不产生新的写入
- [ ] 服务端不返回验证符时，退化为「修改时间 + 大小」判定
- [ ] 远端验证符、修改时间、大小**任一不同**即触发下载确认（这条兜住「验证符失真」的服务端）
- [ ] 上传带 `If-None-Match: *` 保护创建；`If-Match` 尽力而为但不作为正确性保证
- [ ] 显式设置请求超时
- [ ] 单测覆盖：仅本地改 / 仅远端改 / 两侧都未改 / 验证符失真（内容未变仍换验证符） / 无验证符 / 修改时间与大小均未变
- [ ] 单测能证明「验证符相同」不被当作内容相同的**结论**
- [ ] `npm test` 全绿
