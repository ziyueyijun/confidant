# 02: 首次同步——保守合并，带进度与取消

**What to build:** 用户点「同步」发起一次同步，应用扫描工作区与远端根，把两侧内容互相补齐：本地有远端没有的上传，远端有本地没有的下载，同名同内容视为已同步。**一个字都不删。** 页脚状态条实时显示「同步中 123 / 540」并可点取消；结束后显示「上传 3 / 下载 2」这样的摘要。同步状态表按工作区落地，记住每个文件这次的**基准版本**。同步前强制 flush 待保存内容，同步期间允许继续编辑。

规格依据：决议 6–19、29–34、50–55。

## 本票额外承接：传输层与自签证书（01b 交付时暴露的缺口）

01b 把「信任此服务器的证书」开关**存下来并透传**了，但**没有任何代码消费它**：`packages/sync` 默认走全局 `fetch`，Node/Electron 的 `fetch` 不接受自签证书，于是自签服务器**根本连不上**。

决议 41 与票 08 都要求这个开关可用（绿联默认 HTTPS 端口 5006 的证书链不完整）。所以本票在 `src/main` 侧提供**注入的传输层**：

- 用 Node 内置 `node:http` / `node:https` 实现一个 `FetchLike`（**不加新依赖**：`undici` 需额外安装，Node 的全局 `fetch` 无法在不引入 dispatcher 包的前提下按请求关闭证书校验）；
- `trustSelfSignedCert` 为真时，仅对该请求用 `rejectUnauthorized: false` 的 agent；**默认路径必须走完整证书校验，绝不静默接受任何证书**（决议 41）；
- `packages/webfake` 补一个自签 HTTPS 模式 + 配套用例（默认可连的信道 + 自签信道仅在该开关下可连）；证书可用内置的自签夹具。
- `http` 保持可用（决议 40）；`trustSelfSignedCert` 对 `http` 无影响。

- `lib/merge.ts` 的 `buildPlan()` —— 纯决策表。本票下，**所有「本应删除」的组合一律产出 `defer`（空操作），绝不删任何一侧**。

- `lib/conflict.ts` —— 冲突副本命名与防撞（票 04 在此细化）。
- `lib/lock.ts` —— userData 侧锁（`SyncBusyError`）。
- `lib/fs-local.ts` —— 独立本地枚举（**不跟随符号链接**）+ 硬排除名单 + 上限。
- 已标注的插入点：熔断（`buildPlan`/执行循环之间）、列举闸门（`scanRemote` 之后）、冲突标记与计数（`resolveConflict`）、增量探测（`remoteEntryChanged`）、收尾比对（`report.remainingLocalChanges`，现恒 0）。

### 规格未明而由实现裁决的三点（**请用户在票 04 处一并复核**）

1. **首次同步「同名不同内容」的收敛**。规格只说「远端版本落成冲突副本」，**没说是否覆盖远端主名**。实现为：本地主名不动；远端版本落成本地冲突副本并上传为远端新文件；**本地版本覆盖远端主名**。终态两侧都是「主名=本地版本 + 副本=远端版本」，下一次同步稳定无操作。
   - 理由：不覆盖远端主名会让「基准 hash」永远不等于远端现值，破坏三方合并语义（此后远端的任何合法修改都会被误判为冲突）；而要绕开就得在状态表里存「远端现值 hash」而让基准失去意义。
   - 代价：远端主名被本地版本替换。**远端那一份内容并未丢失**（已存于副本），且这符合「本地是权威副本」的取向。
   - **若用户裁决应为「远端主名不动」**，改点是 `engine.ts` 的 `resolveConflict()` 与状态表里该文件的基准记账口径 —— 只此一处。
2. **冲突后基准记为本地内容**（因本地版本已同步到远端主名）。
3. **首次「同名同内容」判定必须 GET 远端算 hash**（WebDAV 无内容 hash）。首次同步对每个同名文件都会 GET 一次，**即使内容相同**。选了安全侧，未接受「同 size 即同内容」的弱判定（那正是决议 35 排除的失真源）。代价是大库首次同步流量偏高。

### 其他实现裁决

- 远端**空目录**不会在本地创建（仅文件驱动）；本地空目录会逐级 MKCOL 到远端。规格未明说。
- 认证失败按整体 fatal 处理；列举失败/404 直接整体失败。与票 06 的范围有重叠，若 06 需要不同语义须调整。
- 传输层未处理重定向与响应自动解压（不发送 `Accept-Encoding`，服务端通常因此不压缩）；真实服务端若强制压缩返回 `content-encoding: gzip`，**解压路径未经真机验证**。
- 锁的陈旧判定用 pid 存活 + 6 小时兜底；同进程重入判 busy。
- 「立即同步」只使用**已保存**的配置；未保存的改动不会被用（用户需先保存）。
