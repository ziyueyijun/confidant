# 07: 启动探测与收尾提示

**What to build:** 启动应用后做**一次只读**的远端探测。若远端存在本机状态表里没有的变更，页脚状态条出现一个小圆点，提示用户该同步了。同一票补上同步循环的收尾比对：同步期间若有文件又被改动，结束时状态条提示「还有 N 个文件的改动未同步」，**不自动重跑**。

规格依据：决议 8、11。

**Blocked by:** [03](03-incremental-change-detection.md)

## Answer

**收官 2026-09-14**（commit `9af516d`，分支 `sync-07`，已并入 `feat/webdav-sync`）。

三件套实测：`npm run typecheck` 通过；`npm test` **409 用例 / 47 文件全过**（票 05 后 383/44，本票 +26）；`npm run lint:boundaries` 零违规（196 模块）。

### 探测（`packages/sync/lib/probe.ts` 的 `probeRemoteChanges`）

**只读**是该模块的红线，实现上：状态表唯一访问是 `store.load()`（读），客户端只调 `list`（`scanRemote` 深度 1），无 PUT/DELETE/本地写。测试 F1 断言探测前后状态文件的字节与 mtime 完全不变。

「未配置不发请求」的两道门：主进程 `probeSyncRun` 在未配置/未解密时**建客户端之前**返回；`probeRemoteChanges` 在 `remoteBaseUrl` 为空时也在 `createClient` **之前**返回。测试 D 断言 `createClient` 调用数为 0、服务端零请求。

「不做轮询」测试 E1：一次探测只建一个客户端、只列举一次远端根。

失败三类（离线 / 认证 / 列举 500）全部 catch 为 `status:"failed"`，**不抛给启动路径**。

### 收尾比对（`countRemainingLocalChanges`）

`engine.run()` 执行循环之后：重扫本地；与本次 run 开始时的元数据（`mtimeMs` + `size`）不同的文件（含同步期间新增的）再算 SHA-256，与**同步后的基准**（重新 `store.load()`）比较，`hash ≠ 基准` 才算未同步。引擎自己写的下载落盘 / 冲突副本基准已对齐，故不计入。只计数，**绝不重跑**（测试断言新建文件未被上传）。

### ⚠️ 已知缺口：远端删除不点亮圆点（**建议代码审查时裁决**）

圆点只由「远端**存在**的条目本机未知 / 已变」触发 —— 探测只遍历 `remote.files`，**远端删掉一个本机有记录的文件时圆点不亮**。

这是对票面「复用 `remoteEntryChanged`」的忠实实现（票 03 导出时即说明该函数只覆盖「存在且已变」），但**决议 8 的原话是「远端存在本机状态表里没有的变更」**，远端删除本身就是一种变更。两者措辞两可。

实现者按「与引擎的删除判定语义保持一致」取了保守解。**但后果是：用户在远端删了文件，直到手动点同步之前得不到任何提示。** 若要覆盖，探测需再加一条与引擎一致的「记录仍在、远端已无」判定（改点在 `probe.ts` 的 `changeCount` 循环）。

**本项留给 `/code-review` 裁决**，不在本票内自行改动。

### 其他未敢确认的假设

1. **「同步完成后圆点消失」实现为仅 `ok` 清除**；`cancelled` / `error` 保留圆点（未真正完成，远端变更未必纳入）。改点在 `probe-gating.ts` 一行。
2. 圆点是纯渲染层 UI，**未做组件级断言**（本仓无 @testing-library），只对门控纯逻辑（`probePathFor` / `dotClearedByOutcome`）做了单测；圆点实际显隐未自动化。
3. **收尾比对不计本地删除**：只统计「改动 / 新增」，同步期间用户删掉的文件不计（按「改动」口径）。
4. 元数据筛选的极端边界：同大小且 mtime 落在文件系统时间戳粒度内的改动会漏计（依赖 NTFS 100ns，实际风险极低）。
5. 未加 `smoke.ts` 探针（工程简报归票 08）。
6. 真机服务端行为（离线 / 认证 / 目录不可达的实际错误形态）未实测，归票 08。
