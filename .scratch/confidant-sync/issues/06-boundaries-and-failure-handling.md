# 06: 边界与失败处理

**What to build:** 无法安全处理的条目被**跳过并列出来**，计入「未完成」而不是算作成功——用户能看到「498 / 500 已同步，2 个跳过（文件名含非法字符）」。涵盖：超过大小上限的文件、符号链接（不跟随）、文件名含 Windows 非法字符、大小写冲突、超长路径、未知条目类型。

失败处理：单个文件传输失败重试 2 次（指数退避）后跳过，**不影响其他文件**；用户名或密码错误立刻停下并提示，不反复重试（避免触发服务端登录失败锁定）；整体失败给出错误摘要与「重试」入口，错误信息遮蔽密码。中断：同步未完成时关窗弹一次确认，确认后取消、落盘、正常关窗（**不阻止关窗**）；切换工作区时当前同步被干净取消。日志写入本机滚动文件，不含密码。

### 「不算作成功」的口径（决议 62）三处保证

1. **引擎报告**：`SyncReport` 的 `uploaded` / `downloaded` 与 `skipped` / `failed` 是并列字段，跳过项只 `report.skipped.push`，**从不进成功计数**。
2. **决策表**：`merge.ts` 新增 `unmanaged` 集合，跳过项一律 `continue`、不产出任何计划项 —— 这一条**同时挡住**「跳过被误当成功/失败」与「跳过被误当对方已删」。
3. **文案**：`formatSyncOutcome` 里 `synced = uploaded + downloaded`、`total = synced + conflicts + skipped + failed`，跳过与失败**只进分母**。断言：`已同步 498 / 500，2 个跳过(…)`，并有反例断言 `not.toContain("已同步 2 /")`。

### 中断语义实现位置

- **关窗**：`src/main/index.ts` 的 `armCloseFlush()` → `handleCloseInterrupt()`（`src/main/sync-interrupt.ts`）：同步中弹一次「同步尚未完成(已完成 X / Y)，关闭将中断。」+「已完成的进度会保存。」；确认 → `cancelSyncRun()` 并继续 flush 后 `win.destroy()`（**不阻止关窗**）；否认 → 不关。
- **切工作区**：`IPC.workspaceOpen` / `IPC.workspaceClose` 处理器首行 `cancelSyncForWorkspaceSwitch(...)`。
- 落盘保证来自引擎既有的「每完成一个文件写一次状态表」；边界测试断言取消后已完成文件记录在状态表、未完成不写。

### 熔断确认接线

`src/main/sync-run.ts` 的 `confirmDeletesViaDialog`（经 `deps.confirmDeletes` 注入）→ `dialog.showMessageBox`；文案由 `sync-interrupt.ts` 的 `buildDeleteGuardMessage` 生成，**默认按钮为「取消(不删除)」**，用户不主动确认即零删除。**票 05 遗留的「删除功能不可用」缺口就此关闭。**

### 已知缺口

- **取消不中断在飞请求**：`AbortSignal` 只在两个计划项之间检查，关窗后一个正在进行的 HTTP 请求最多拖到 30s 超时进程才真正退出。窗口已销毁，但「正常关窗」的体感可能延迟。要更利落需把 signal 透进客户端的 `AbortController`。
- **大小写冲突只查同一目录列举内**：「远端 `Note.md` vs 本地 `note.md`」这类跨侧仅大小写不同未识别（是两个不同键），在大小写不敏感的本机可能互相覆盖。**归票 08 真机复核**。
- 只跳过**会落到本地的**超长路径（远端）；本地超长路径不跳过（文件已存在，不构成不安全）。
- `Footer` 重试按钮无组件渲染测试（`isRetryable` 逻辑有单测；仓库无 Footer 测试夹具）。
- 跳过项被 `unmanaged` 排除后，其另一侧的删除/新增会**一直**被推迟到能处理为止（保守但可能长期滞留）。

### 未敢确认的假设

1. `WINDOWS_MAX_PATH_CHARS = 260`，按「工作区根长度 + 1 + 相对路径长度」判定；若系统已启用长路径支持，本实现更保守（只跳过，不丢内容）。
2. 「整体失败重试入口」放宽为：状态 error **或**存在失败项时都显示「重试」。
3. 关窗「弹一次」实现为「每次关窗尝试弹一次」；用户否认后再关会再弹。
4. 日志/失败原因遮蔽依赖注入的 `redact`；生产由 `sync-run` 传 `redactSecrets`。
5. 认证错误统一转 `SyncFatalError("用户名或密码错误。")` 也覆盖 403：非认证语义的 403 会被同样提示（偏安全，提示可能不够精确）。
