# confidant WebDAV 同步规格

> 本规格由 2026-09-14 的访谈逐题裁定后汇编而成，决议共 68 条（实现决议 1–64，测试决议 65–68 及接缝决议）；调研依据与来源见 Further Notes，未验证项见 Further Notes 的「待验证清单」。

## Problem Statement

confidant 是本地优先的 Markdown 笔记，工作区就是用户自己选的一个普通文件夹。用户在多台电脑上使用同一个知识库时，目前没有任何同步手段：只能靠 OneDrive、坚果云这类网盘客户端在文件系统层面搬运。网盘客户端不理解「应用正在编辑哪个文件」，于是产生冲突副本、半写文件与静默覆盖。

用户自建了 WebDAV 服务（绿联 NAS），希望由应用自己承担同步：**把当前打开的工作区与 WebDAV 服务器上的一个目录保持双向一致**。

一个必须先处理的前提：首版建图时把「云同步/多端」列为 Out of scope，理由是「与本地优先原则直接相抵」。本次范围变更及其收窄解释见 ADR-0001。

## Solution

在 confidant 中新增 WebDAV 同步，形态是**文件级、双向、手动触发**。

- **文件级镜像**：远端目录是工作区内容的逐文件副本。远端上的 `.md` 与图片可以被任何 WebDAV 客户端直接打开、阅读、拷走。不是快照包，不是哈希对象仓库（对比见 ADR-0002）。
- **双向**：本地改动推到远端，远端改动拉到本地；两端都改了同一个文件时保留双份。
- **手动触发**：用户点按钮才同步。应用只在启动时做一次只读探测，发现远端有本机不知道的变更就在页脚状态条提示。
- **绝不静默丢内容**：这条不变量是本方案全部保护措施的来源——删除双向传播但走 Windows 回收站、大面积删除熔断、冲突保留双份、无法处理的条目一律报告、远端列举可疑时立即停止。

配置粒度是**每工作区一份**，入口在「文件 → 同步设置…」。凭据经 Electron `safeStorage` 加密后存放于本机状态文件，不进工作区，也不进远端。

## User Stories

1. 作为用户，我想要在「文件 → 同步设置…」里为当前工作区配置同步，以便不必离开工作区上下文去别处找设置。
2. 作为用户，我想要填入 WebDAV 地址、用户名与密码，以便把这个知识库同步到我自己的服务器。
3. 作为用户，我想要一个「测试连接」按钮，在保存配置前就能知道地址是否可达、认证是否通过，以便在出事之前发现配置错误。
4. 作为用户，我想要在远端目录非空时收到一次明确说明，以便确认我没有连错目录。
5. 作为用户，我想要看到「远端以明文存储，请确认你信任该服务器」这句话，以便在知情的前提下决定要不要启用。
6. 作为用户，我想要在地址是 `http` 时被明确告知密码会明文过网，以便决定是否改用 `https`。
7. 作为用户，我想要一个「信任此服务器的证书」开关（默认关闭），以便能连上局域网里用自签证书的 NAS。
8. 作为用户，我想要密码被记住且不必每次输入，以便日常使用不烦人。
9. 作为用户，我想要密码以本机账户绑定的方式加密保存，以便它不会被别的程序或别的 Windows 账户直接读走。
10. 作为用户，我想要换电脑或换 Windows 账户时被提示重新输入密码，而不是看到一个无法解释的失败。
11. 作为用户，我想要一个明确的「同步」按钮，以便我完全掌控什么时候产生网络流量。
12. 作为用户，我想要在页脚状态条看到「同步中 123 / 540」，以便知道它确实在动而不是卡死。
13. 作为用户，我想要一个取消按钮，以便一次误点的全量同步能停下来。
14. 作为用户，我想要在同步结束后看到结果摘要（上传 3 / 下载 2 / 冲突 1 / 跳过 2），以便知道刚才发生了什么。
15. 作为用户，我想要在启动后发现远端有本机不知道的改动时看到一个小圆点，以便不会忘记同步。
16. 作为用户，我想要在同步进行中继续编辑我的笔记，以便不被同步打断。
17. 作为用户，我想要在同步结束时被告知「还有 N 个文件的改动未同步」，以便知道需要再点一次。
18. 作为用户，我想要在两端都改了同一个文件时，两边的版本都被保留下来，以便任何时候都不丢内容。
19. 作为用户，我想要冲突副本以可读的文件名落在我原来的笔记旁边，以便我自己打开对照。
20. 作为用户，我想要冲突副本在文件树里带标记，以便一眼看出哪些文件出过冲突。
21. 作为用户，我想要冲突副本也会同步到远端，以便第二台机器也能看到这个冲突。
22. 作为用户，我想要删除双向传播，以便在任何一台设备上的删除都会反映到另一台。
23. 作为用户，我想要本地被删除（无论是我删的还是同步删的）的文件进入 Windows 回收站而不是被抹掉，以便还能捞回来。
24. 作为用户，我想要在单次同步要删除的文件异常多时被拦下来确认，以便误连地址或 NAS 失联不会删光我的笔记。
25. 作为用户，我想要在第二台电脑上首次启用同步时执行保守合并（只补不删），以便可以放心地在已有数据的工作区上启用。
26. 作为用户，我想要远端目录上看到的是我真实的 `.md` 与图片文件，以便我用任何别的工具也能读它们、拷走它们。
27. 作为用户，我想要应用不去动 `.git`、`.DS_Store`、它自己的临时文件这类东西，以便同步不会把无关内容推上去。
28. 作为用户，我想要在超大文件被跳过时被告知，以便知道它没同步，而不是以为同步完成了。
29. 作为用户，我想要符号链接被跳过，以便我工作区里指向别处的链接不会把工作区外的内容传到服务器上。
30. 作为用户，我想要文件名含非法字符、超长路径这类无法处理的条目被列出来，以便我知道哪些文件没有同步，而不是它们悄悄消失。
31. 作为用户，我想要单个文件失败时其他文件继续同步，以便 500 个文件里的第 300 个失败不会让前 299 个白做。
32. 作为用户，我想要在用户名或密码错误时立刻收到明确提示而不是反复重试，以便不会触发服务端的登录失败锁定。
33. 作为用户，我想要在整体失败时看到错误摘要和一个重试入口，以便不用重新配置一遍。
34. 作为用户，我想要在同步未完成时关窗被问一次，以便不会莫名中断。
35. 作为用户，我想要切换工作区时当前同步被干净地取消，以便不会在看不见的工作区上继续写文件。
36. 作为用户，我想要工作区改名或移动后，设置界面明确告诉我「未找到该工作区」，以便不会以为同步还在工作。
37. 作为用户，我想要在把工作区放在 OneDrive 这类同步目录里时被提醒一句，以便知道两个同步系统可能在打架。
38. 作为用户，我想要每个工作区只对应一个远端目录，以便配置的含义始终清楚。
39. 作为用户，我想要多个工作区的同步按顺序执行，以便不会同时压垮服务器。
40. 作为用户，我想要同步日志能查，但密码不出现在里面，以便排查问题时不泄露凭据。

## Implementation Decisions

### 范围与原则

1. **收窄**首版的「云同步/多端」划出条款：它约束的是「把数据托管给第三方云服务」，不约束「用户自己的 WebDAV 服务器」。数据仍是本地普通 `.md`，同步只是传输通道。范围变更记入 ADR-0001。
2. 远端始终保持**纯文件夹**：应用自己的任何文件（清单、索引、缓存、版本目录）都不写进去。这条排除了「远端放同步清单」与「远端版本历史」两个方案。
3. 同步是**文件级镜像**，不是快照式整包，也不是哈希对象仓库。记入 ADR-0002。
4. **远端内容以明文存储**。同步设置界面必须明确写出「远端以明文存储，请确认你信任该服务器」。理由：加密与第 2、3 条在逻辑上不相容——不能既要「远端是任何工具都能打开的普通文件」，又要「服务端看不到明文」。需要加密时不是给本方案加选项，而是换方案。
5. **兼容性**：实现层不做任何服务端特判，改用**能力探测**（从远端属性响应读取服务端实际提供了什么）。首版实测目标是**绿联 NAS**；其他服务端登记为「待验证」，见 Further Notes。**待验证清单不阻塞首版收官**。

四条已确立的架构结论：

- **远端不需要清单文件。** 判断「谁做了什么」所需的历史基准存在**本机**状态表里就够。例：机器 A 删了笔记 Y 并推到远端，机器 B 的状态表里存着 Y 的基准版本；B 看到「本地有 Y、远端没有 Y」——本地内容等于基准说明 B 没动过，是远端删的；不等于则说明 B 也改过，是冲突。该推断只用 B 自己的状态表。
- **同步状态表放本机 `userData`**，以工作区绝对路径为键（仓库已有先例：树展开记忆）。不写进工作区，不写进远端。
- **不识别「改名」。** 文件监听只有删除与新增两个事件，改名与「删除 + 新建」不可区分。首版按后者处理：远端删旧名、传新名。结果正确，代价是远端多两次操作。移动优化留到以后。
- **同步写本地文件时复用仓库现有的「外部变更」通道**，不另建通知。同步引擎**不注册**自身操作回声抑制——这里恰恰需要编辑器重载。前提是同步前已 flush（见第 9 条）。

### 同步语义

6. **双向**同步。
7. **手动触发**。不做自动同步，不做定时同步。
8. **启动时一次只读探测**：对远端根做一次列目录请求，若远端存在本机状态表里没有的变更，页脚状态条显示一个小圆点。**不做轮询**。
9. 同步前**强制 flush** 全部待保存内容（复用关窗保护用的那套机制）。
10. **同步进行中允许编辑**，不锁定编辑区。
11. 同步结束时做一次**收尾比对**：若有文件在同步期间又被改动，在状态条提示「还有 N 个文件的改动未同步」。**不自动重跑**（否则用户持续输入时同步会一直循环）。
12. 同步进行中「同步」按钮禁用，不做重入。多个工作区的同步任务**串行**执行，一次一个。
13. 同步是**字节级搬运，不经过编辑引擎**。远端文件原样下载，本地文件原样上传。这保证 front matter 字节保留不变量，也让未被应用打开过的文件在多机之间保持字节一致。
14. **请求串行，并发数为 1**。任何时刻只有一个未完成的请求。依据见 Further Notes「思源的先例」。

### 范围与排除

15. 同步工作区**整棵目录树**，含图片、PDF 及其他非 `.md` 文件。
16. **硬排除名单（不可关闭）**：所有**点开头条目**（一次覆盖 `.git`、`.DS_Store` 与应用自己的原子写临时文件），以及 `Thumbs.db`、`desktop.ini`。点开头这条与现有工作区树扫描行为一致。代价是用户自己的点开头配置目录不会被同步——这一点要在界面上写明。
17. **单文件上限 100 MB**。超出的文件跳过并计入报告，**不算失败**。
18. **不跟随符号链接**，跳过并计入报告。注意：现有工作区树扫描**会**跟随符号链接（带 realpath 防环），所以同步模块必须显式声明这条，不能复用那份逻辑。
19. 不做自定义排除规则输入框。

### 冲突与删除

20. 状态表为每个文件记录**上次同步时的内容 hash，作为基准版本**。
21. **冲突判定**：本地内容与远端内容**都离开了基准版本** → 冲突。
22. **冲突处置 = 保留双份**。本地文件保持不动，远端版本以如下形式落在同目录：

    ```
    笔记名 (冲突 来自远端 2026-09-14 15-30-12).md
    ```

    时间戳用 `-` 分隔（`:` 在 Windows 文件名中非法）。图片等非 `.md` 文件沿用同一模式并保留原扩展名。**不做自动三方合并**：自动合并需要额外保存每个文件的基准内容副本（状态表随之膨胀，且等于在本机状态文件里存下第二份笔记），而 Markdown 的自动合并对表格、代码块、front matter 都不可靠。升级路径保留——基准 hash 已在记录，将来补存内容即可。
23. 冲突副本本身是普通文件，会照常同步到远端，因此第二台机器也能看到这个冲突。
24. **删除双向传播**。
25. **本地删除永远走 Windows 回收站**，不用不可恢复的删除。与仓库现有删除行为一致，用户永远能从回收站捞回。
26. **远端删除的判定必须靠基准版本**：只有状态表里有该文件记录、**且**本地内容仍等于基准时，才认定为「远端删除」。本地内容已变 → 冲突（改 vs 删）→ 走第 22 条保留双份。
27. **熔断阈值**：一次同步中，若「要删除的文件数」**超过 20 个**，**或超过该侧文件总数的 20%**，立即停止并要求用户确认。百分比规则用于覆盖小工作区（3 个文件的库删 3 个也会触发）。
28. 用户从服务端回收站恢复文件后，同步会正确地把它当作「远端新增」拉回本地（状态表里该记录已清除）。这是设计内行为，写进文档。

### 首次同步

29. **本机没有状态表**（首次为某工作区启用同步）= **保守合并**，**绝不删除任何文件**：同名同内容视为已同步并记录基准；同名不同内容两份都保留（远端版本落地为冲突副本）；只在一侧存在视为新增并补到另一侧。
30. 远端目录非空时首次配置 → 弹一次确认，明确说明：「远端目录已有内容。首次同步会执行保守合并：同名同内容视为已同步，同名不同内容两份都保留，只在一侧存在的文件补到另一侧。**不会删除任何文件**。」
31. 该确认只在**本机第一次配置该工作区**时出现。

### 状态与存储

32. **同步状态表**位于本机 `userData`，以工作区绝对路径为键。每个文件记录：相对路径、基准内容 hash、远端验证符（ETag）、远端修改时间、远端大小、删除墓碑。
33. 状态表**读取失败 → 退化为「无状态表」→ 走保守合并**（第 29 条）。**绝不静默重建为空表**再据此删文件。
34. 状态表**每完成一个文件写一次**（不是单个事务）。中断后已完成的进度保留，未完成的文件在下次同步时重新判定。
35. **远端验证符只做变化探测，内容 hash 才是唯一权威。** 远端条目的验证符、修改时间、大小**任一不同**即下载并算 hash 确认。依据见 Further Notes：多个服务端的验证符有已知缺陷。
36. 凭据解密失败（换机器、换 Windows 账户）→ 提示重新输入密码。
37. **锁文件**防止两个应用实例同时同步同一工作区。

### 连接与安全

38. **所有网络请求在主进程**发起，渲染层不碰网络。理由：现代 WebDAV 用的非简单请求方法从渲染层发出会被 CORS 预检拦住，而 WebDAV 服务端不会返回正确的 CORS 头。
39. 认证方式只做 **Basic**。
40. 允许 `http` 与 `https`。**`http` 必须明确警告密码明文过网**。
41. **自签证书**：提供「信任此服务器的证书」开关，**默认关闭**，开启时明确警告。绝不静默接受任何证书。
42. 凭据经 Electron **`safeStorage`**（Windows 下走 DPAPI）加密后写入本机状态文件。
43. **日志必须遮蔽密码**。同步日志写入本机的滚动日志文件以便排查。
44. **自研薄 WebDAV 客户端**，只实现列目录、下载、上传、删除、建目录、移动六个动词，外加一个小 XML 解析依赖。**不使用现成的 `webdav` npm 包**。理由与代价见 ADR-0003。
45. 列目录**只用深度 1**，逐层遍历。不使用无限深度（部分服务端明确拒绝）。
46. **建目录逐级创建**，一次只建一层。**400 与 405 都当作「已存在」**。绿联 NAS 对已存在的共享根目录返回 400（非标准的 405），且对多级建目录返回 405 后会让后续上传连环失败。
47. 上传后**回读校验大小**，不一致则计为未完成。
48. 创建用 `If-None-Match: *` 保护（防止覆盖同步期间被别处创建的文件）；`If-Match` 尽力而为，但**绝不作为正确性保证**——服务端支持度参差，正确性来自同步前的状态比对与同步后的校验。
49. 显式设置**请求超时**。

### 界面与交互

50. 入口：**主窗口菜单「文件 → 同步设置…」**，打开工作区级对话框。理由：配置的作用域是工作区，入口也应是工作区级；偏好设置窗口是应用级的，不承担工作区级配置。
51. 只粘贴**完整 URL**，不做远端目录浏览器。每个工作区只允许配一个远端。
52. 配置项：地址、用户名、密码、「信任此服务器的证书」开关，加一个**「测试连接」**按钮。
53. 进度：页脚状态条显示「同步中 123 / 540」+ **取消**按钮。
54. 结果：页脚状态条显示文字结果（如「已同步 · 上传 3 / 下载 2」「完成，产生 1 个冲突」「已同步 498 / 500，2 个失败」）。
55. 冲突副本在文件树里带标记（复用仓库既有的「文件缺失」状态标记模式）。
56. 工作区被移动或改名 → 设置界面明确显示「未找到该工作区」，不静默失效。
57. 启用同步前，若检测到工作区路径落在常见网盘同步目录内，**给出一次警告但绝不阻止**。检测是启发式的（OneDrive 有环境变量可直接读，其余按路径名判断），因此**只用于提示，不参与任何自动决定**。

### 健壮性与边界

58. **单文件失败重试 2 次**（指数退避），仍失败则跳过、记入报告、**继续同步其他文件**。
59. **认证失败单独识别**，直接停下并提示「用户名或密码错误」，不重试（重试无意义，还会触发服务端登录失败锁定）。
60. **整体失败**（连不上、认证失败、熔断触发）→ 状态条显示错误摘要 + 一个「重试」入口。错误信息中必须遮蔽密码。
61. **无法安全处理的条目**一律**跳过 + 报告 + 计入「未完成」计数**：远端大小写冲突（`Note.md` 与 `note.md` 并存）、Windows 非法字符（`: * ? " < > |`）、超长路径、超过上限的文件、符号链接、未知条目类型。
62. **绝不静默丢弃，绝不把跳过的算作成功。** 状态条必须能说出「498 / 500 已同步，2 个跳过（文件名含非法字符）」这种话。
63. **列举闸门**：远端根列举返回 **0 条**，而本机状态表里**存在**该远端的历史记录 → **立即报错并停止**，不做任何删除。列举返回非成功状态码 → 一律视为整体失败，绝不当作「远端为空」。依据见 Further Notes：已知存在「上传正常、列举静默为空」的客户端编码缺陷，而它一旦与删除传播相遇就是「本地全删」。
64. **中断语义**：点取消 → 立即停止，已完成的操作保留，未完成的待下次重新判定；关窗时同步进行中 → 弹一次确认「同步尚未完成（已完成 123 / 540），关闭将中断。已完成的进度会保存。」，确认后取消、落盘、正常关窗，**不阻止关窗**；切换工作区 → 取消当前同步并落盘。

## Testing Decisions

**接缝只有一条，放在 HTTP 传输层。** 测试注入一个假的 WebDAV 服务器（内存文件表 + 按 WebDAV 语义应答）。于是**同步引擎、状态机、WebDAV 客户端、XML 解析、路径归一化全是真的**，只有网络是假的。

选在这里的理由有三条：接缝只有一条；引擎与客户端**同时**落在测试覆盖下；而最危险的场景——第 66 条要求的那批畸形响应——**本来就只能在 HTTP 层表达**，若把接缝放在「六个动词」的语义端口上，假对象会顺手把它们修好，永远测不到。

配套约束：

- **本地文件系统不注入**，走真实临时目录（与仓库既有的磁盘服务测试一致）。不造假文件系统。
- **阈值类参数（100 MB 上限、熔断的 20 个 / 20%）进入配置对象**，测试传极小值，避免在测试里造大文件和几百个文件。
- **进度与取消**是同一个调用的回调与中止信号参数，**不算新接缝**。

测试只测**外部行为**，不测实现细节：断言的是「给定本地目录、远端目录与状态表这三方的初始状态，同步之后三方的终态与返回的报告是什么」，而不是「调用了哪几个内部函数」。HTTP 请求的形状属于本功能的外部契约（我们要与真实服务端对接），因此可以被断言。

65. **状态机穷举单测**。把「本地状态 × 远端状态 × 状态表」的每一种组合跑成用例：新增 / 修改 / 删除 / 冲突 / 首次 / 熔断。真实临时目录 + 内存假服务端。参照仓库既有的引擎 `normalization-matrix` 那类矩阵式测试的写法。
66. **假服务端必须能模拟畸形行为**：多级建目录返 405、对已存在集合返 400、不返回验证符、文件名含 XML 实体（`&`、`<`）、列举静默返回空、非 ASCII 与含空格路径。这些在真机上测不出来，但都真实发生过。
67. **真机冒烟**：环境变量驱动的脚本连绿联 NAS 跑一遍竖切（配置 → 测试连接 → 首次保守合并 → 改动 → 双向同步 → 冲突 → 删除），复用仓库现有的自检/冒烟模式，并遵守它「每次用全新目录或重建夹具」的约定。
68. **验收 = 65 + 66 + 67 通过 + 人工验收。**

界面侧的纯逻辑（结果文案、状态归纳）随实现与源文件同目录放单测，与仓库现有做法一致；跨进程的那条链路由第 67 条的真机冒烟覆盖。

## Out of Scope

- **不做内容加密**（第 4 条）。远端是明文。
- **不做版本历史**，不做远端版本目录。
- **不做自动三方合并。**
- **不做差异对比面板**，不做同步历史面板。
- **不做远端目录浏览器**（只粘贴完整 URL）。
- **不做自定义排除规则输入框。**
- **不做定时轮询**，不做自动同步。
- **不做并发请求**（串行，见第 14 条）。
- **不做改名识别**与移动优化。
- **不做服务端特定适配分支**（只做能力探测）。
- **不做单向模式**（只推不拉 / 只拉不推）。
- **不做目录级的原子提交**——状态表按文件写，中断后靠重新判定收敛。

## Further Notes

### 调研依据

来源为 2026-09-14 的两次调研（服务端能力与客户端库；思源笔记同步机制）。

**服务端**

- 绿联 NAS（UGOS Pro）：WebDAV 是「控制面板 → 文件服务」内置项，默认端口 HTTP 5005 / HTTPS 5006。多级建目录返 405 并导致后续上传连环失败（rclone#9010）；对已存在的共享根目录建目录返 400（cc-switch#5621）；5006 证书链不完整（home-assistant#163109）。实现组件与移动动词的支持情况**未查到**。
- 远端验证符的已知缺陷：Nextcloud（SabreDAV）「同一秒内覆盖文件验证符不变」（server#63994）、「内容未变验证符仍变化」（server#58978）；Apache `mod_deflate` 会改写验证符导致条件上传全部 412；Alist 的集合根本不返回验证符（alist#5491）；rclone 的验证符由修改时间与大小拼出。弱验证符无稳定返回的一手证据。绿联与坚果云的行为**未查到**。
- 无限深度列举被拒：Synology、SFTPGo。现成的 `webdav` npm 包不支持 `If-Match`，且有一个未修复的高优先级缺陷——不解码 XML 实体（webdav-client#276）。
- 编码陷阱：路径含非 ASCII 时前缀匹配可能永不命中，导致**列举静默清空**（「上传正常、列举为空」，deep-student 项目的一手注释）；文件名含 `%` 与 `#` 在 Nextcloud 上会坏掉（server#57353）。
- WebDAV 协议本身**没有回收站概念**（RFC 4918 全文无 trash/recycle）。Nextcloud 的回收站是私有扩展；绿联 NAS 有回收站。
- 坚果云硬限制：免费版 600 次请求 / 30 分钟、付费版 1500 次；单次请求上限 750 个条目。思源笔记在代码层面直接按端点拦截坚果云（siyuan#7657）。

**思源的先例**

思源自研了一套类 Git 的数据仓库（dejavu）：内容定义分块、SHA-1 寻址、AES 加密。它的 WebDAV 目录里**看不到用户的文件**，只有索引、对象与引用。

对我们有直接参考价值的部分：

- 它的内置忽略规则**就是**「以 `.` 开头的文件和目录」+ 临时文件 + 隐藏文件 + 符号链接——与第 16、18 条一致。
- 它用内容 hash 而非远端验证符（整个仓库内容寻址）——与第 35 条一致。
- 冲突时生成标题带「(Conflicted 年-月-日 时:分:秒)」的新文档——与第 22 条同构。
- 云端有同步锁对象防并发同步——与第 37 条同构。
- v3.1.10 加了并发数设置，**WebDAV 默认 1**，发布说明原文：「某些 WebDAV 服务端实现不支持并发请求，配置为 1 可以提升稳定性」——第 14 条的依据。
- 它的数据丢失史是反面教材：v2.10.15「数据同步误删本地文件」（siyuan#9631）、v3.4.2「数据同步可能错误覆盖数据」（siyuan#16460）、密钥重置后持续 401（siyuan#17600）。
- 官方明确只支持多设备**交替**同步：「无法支持多设备同时同步，这样会发生无法预期的数据覆盖」。本方案用基准版本判定 + 保守合并覆盖了这个场景。
- 它的 WebDAV 密码**明文**存在本机配置里（siyuan#13137）——第 42 条的反面依据。

**代码事实（动工前值得先核对的现状）**

- 工作区树扫描只收目录与 `.md` 文件，**图片不在其中**；不返回修改时间、大小或 hash。同步需要自己的一层枚举与探测。
- 工作区是纯文件夹，**没有任何应用自有隐藏目录**；原子写的临时文件写在目标同目录，名字形如 `.{文件名}.confidant-tmp-{pid}-{随机}`。
- 文件监听只忽略那个临时文件名，不忽略 `.git` 与 `node_modules`。
- 删除走系统回收站，全仓**没有任何持久删除记录**；改名在监听层不可区分。
- 主进程**零网络代码**；渲染层的 CSP 放开了 `http`/`https`，但 WebDAV 从渲染层发会被 CORS 拦住。
- 全仓**没有「长任务 + 进度 + 取消」设施**；最接近的两个流程（导出 PDF、全工作区搜索）都是「一次调用阻塞返回」。第 53 条要新建这套设施。
- Electron 44.2.0，三个窗口均开启上下文隔离与沙箱。
