## Question

**大纲面板**的决议：侧边栏从单一文件树改为「文件 / 大纲」双 tab，大纲按标题层级生成，交互对齐 Typora，定到可实施的程度。

已定方向（map Notes）：侧边栏加「文件/大纲」双 tab，按 Typora 交互（点击跳转、滚动跟随高亮当前标题）。

待决议：

1. **大纲数据来源**：渲染层从 ProseMirror 文档解析 heading 节点（无需引擎扩展？）还是需要 packages/engine 提供接口——若需扩展引擎，明确接口需求与包边界（engine 只被渲染层引用）。
2. **交互规格**：条目层级缩进与字号、点击跳转（滚动定位 + 光标置入？）、滚动跟随高亮（防抖？）、标题折叠/展开（多级大纲的折叠）、空文档/无标题文档的展示。
3. **与文件树的共存**：tab 切换的形态（Typora 式顶部小 tab）、宽度记忆共享（现状侧栏宽度记忆是否两个 tab 共用）、大纲条目点击是否自动展开侧边栏。
4. **性能**：大文档（数千行）下大纲的实时刷新策略（跟随编辑防抖重建？）。

产出：大纲面板规格（数据来源与接口需求、完整交互规格、性能策略），记录于本票 Answer。

## Answer

（2026-09-07，与用户对话决议；Q35-Q37 全部按推荐。基线依据：票 01 基线 §3.2（双 tab）与 §4.1（大纲面板）。）

1. **数据来源**：渲染层直接解析 ProseMirror doc 树——遍历 heading 节点（层级/文本/位置），**不改 packages/engine**（包边界保持：引擎只管 markdown↔文档转换，大纲是纯 UI 呈现需求）。**源码模式下大纲禁用/空态**（textarea 直写字节时无 ProseMirror doc，Typora 源码模式同款不更新）。
2. **交互规格**：
   - 条目：层级缩进每级 1em（h1 顶格 / h2 1em / h3 2em…，基线 §4.1）；字号随侧边栏 14px；激活项加粗（700，基线 .outline-active）。
   - 点击跳转：滚动定位到标题 + **光标置入标题处** + 编辑器聚焦。
   - 滚动跟随高亮：编辑器滚动时 **rAF 节流**计算视口顶部当前标题 → 大纲高亮对应条目；doc 变化 **300–500ms 防抖重建**（大文档不抖）。
   - **层级折叠**：条目带折叠箭头（基线 Ionicons 8px 展开箭头机制），收起时隐藏其全部子级。
   - 空态：无标题文档显示占位文案（opacity .6，基线空态淡入）。
   - 无需虚拟化（标题数量天然有限，通常 <100 条）。
3. **与文件树共存**：侧边栏顶部「文件 / 大纲」双 tab（宽 84px、激活加粗 + 底部 4px currentColor 色条，基线 §3.2 实测）；**宽度记忆两 tab 共享**（现状拖拽宽度持久化不变）；点击大纲条目**不自动收起侧边栏**（Typora 同款）；**不引入基线的大纲 pin 按钮**（侧栏显隐已有 Ctrl+Shift+B，避免多余状态）。
