# 03-theme-system

Status: resolved
Type: grilling
Blocked by: 01

## Question

**主题系统**的决议：confidant 从「亮/暗两态（data-theme）」升级为「三主题包 + 主题菜单切换」，定到可实施的程度。

已定方向（map Notes）：内置三套主题——github 风亮色（默认）、night 风深色、newsprint 风纸感米黄；菜单加「主题」项切换；CSS 变量架构；视觉数值输入来自票 01-typora-visual-baseline。

待决议：

1. **主题包定义**：每套主题的 CSS 变量集（基于票 01 的基线数值，命名沿用 confidant 现有 `--app-bg`/`--panel`/`--accent` 等体系还是重构变量名？）。
2. **与「跟随系统」的融合**：confidant 现有「视图 → 外观」子菜单（跟随系统/浅色/深色三态）与新「主题」菜单如何共存？newsprint 纸感主题在暗色系统下怎么办？（候选：跟随系统仅作用于亮/暗基调，主题菜单覆盖具体风格；或取消跟随系统，完全 Typora 化只列主题。）
3. **切换机制**：运行时切换的粒度（CSS 变量组整体替换 vs 主题类名切换）；「主题」菜单勾选态维护。
4. **主题化的完整性边界**：哪些界面必须吃主题变量（编辑区/侧边栏/工具栏/浮层/菜单/横幅/滚动条？），哪些允许保持现状（代码高亮 token 已随主题，需纳入三套各一档？）。

产出：主题系统规格（三套主题的变量值、菜单与切换机制、与跟随系统的关系），记录于本票 Answer。

## Answer

（2026-09-07，与用户对话决议；Q21-Q24 全部按推荐。）

1. **变量集**：沿用 confidant 现有语义变量体系，**按需补充、不重构**（Typora 的 :root 变量机制同理，基线 §1/§6-1）。新增 token 按现有命名风格补：`--blur-text`（专注模式淡出色，参照 github `#C8C8C8` / night `#686868`）、侧边栏激活左边框色（`--tree-active-border`，见第 4 条）、工具栏/偏好设置窗口/大纲面板/状态信息条所需组件变量。
2. **跟随系统**：**取消**。「视图 → 外观」子菜单（跟随系统/浅色/深色）删除；「主题」菜单直接列三主题勾选切换（Typora 同构——主题选择即亮暗选择）。删除 `prefers-color-scheme` 媒体查询逻辑。
3. **切换机制**：`data-theme` 三值 `"github" | "night" | "newsprint"`，`:root[data-theme=…]` 三组 CSS 变量整体覆盖；「主题」菜单勾选态沿用 menu-bridge setChecked；use-app-theme 由两态改三态并负责持久化（现有存储字段升级）。
4. **主题化边界**：全组件吃主题变量——编辑区全文（正文/标题/链接/引用/表格/任务列表/front matter 块）、代码块与代码高亮（**每主题一组 token**）、侧边栏（含新文件/大纲双 tab）、格式工具栏胶囊、搜索顶部条、链接面板、横幅/通知/对话框、偏好设置窗口、状态信息条。**滚动条保持 Windows 系统原生**（Typora 仅 night 定制滚动条，confidant 不做）。侧边栏激活态按基线规律 8 对齐 Typora：**背景 + 4px 左边框**（变量 `--tree-active-bg` + 新增 `--tree-active-border`），替代现整行底色。⚠ **newsprint 代码高亮 token 基线未提取**（night 有独立暗色语法文件），实施时从 `themes/newsprint/` 资源补提，蓝图标注来源路径。
5. **三主题变量依据**（票 01 基线 §1）：github 白底 `#fff`/正文 `#333`/链接 `#4183C4`/选中 `#B5D6FC`/侧栏 `#fafafa`/激活背景 `#eee` + 左边框 `#777`；night 背景 `#363B40`/正文 `#b8bfc6`/标题 `#DEDEDE`/链接 `#e0e0e0`/选中 `#4a89dc`/侧栏 `#2E3033`/激活左边框 `#8d8df0`；newsprint 纸底 `#f3f2ee`/正文 `#1f0909`/链接 `#065588`/选中 `rgba(32,43,51,.63)`/侧栏同纸色。间距节奏 24px 系、标题层级比例见基线 §2.2。
