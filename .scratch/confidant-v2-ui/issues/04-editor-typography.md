# 04-editor-typography

Status: resolved
Type: grilling
Blocked by: 01

## Question

**编辑区排版**的决议：confidant 从「60vw 自适应限宽」改为「Typora 式纸张感」，正文排版向参照基线（Typora github 主题，票 01）靠拢并适配中文，定到可实施的程度。

待决议：

1. **内容宽度**：`max-width` 具体值（约 860px？窗口窄时下限？）、左右留白策略、底部滚动余量（现状 40vh 保留否）。
2. **正文排版参数**：字号（16px 调整否）、行距、标题层级（1-6 的 字号/字重/间距）、段落间距、引用/列表/表格/图片/任务列表样式——基于票 01 基线数值，逐项裁定「照搬基线 / 中文适配 / 维持现状」。
3. **front matter 块样式**：现状灰底等宽块，是否 Typora 化（Typora 的 front matter 是折叠的 `<head>` 区）——涉及规格 §4.3 的 front matter 保留约束，样式改动不得影响字节行为。
4. **代码块**：行号/语言标签/复制按钮的视觉并入主题体系（与票 08-find-panel-redesign 的分工：本票定样式，08 定交互）。
5. **字体策略**：UI 字体与正文中文字体（微软雅黑体系维持否）、西文与代码字体、是否引入新字体资产（如 Typora 的 Raleway 系——OFL 许可可用但需评估是否值得）。

产出：编辑区排版规格（宽度策略、逐项排版参数、front matter 与代码块样式、字体表），记录于本票 Answer。

## Answer

（2026-09-07，与用户对话决议；Q25-Q30 全部按推荐。数值依据：票 01 基线 §2.2 与 §5.3。）

1. **内容宽度分级**：860px 起步，视口 ≥1400px → 1024px、≥1800px → 1200px（基线实测 github 规则）；窄窗下限保留现状两侧 ≥16px 留白。替代现 `min(60vw, 100%-32px)` 自适应（60vw 在宽屏上的「论文排版」观感被分级限宽取代）。
2. **标题体系**：对齐基线——h1 `2.25em`(36px)/h2 `1.75em`(28px)/h3 `1.5em`(24px)/h4 `1.25em`/h5·h6 `1em`；统一 bold；**h1/h2 带 1px 下边框**（主题变量，github 基线 #eee）；标题 margin 1rem 上下。替代现 h1 1.7em 系/600 字重/无下边框。
3. **正文与块级**：正文 16px；**行高保留 1.7**（中文适配，不降基线 1.6）；块间距 0.6em → **0.8em**；引用改 **4px 左边框 + 灰字**（github 基线 #dfe2e5/#777 系，吃主题变量；newsprint 主题下按纸感变体）；表格对齐基线（边框 #dfe2e5 系、表头底 + 偶数行底 #f8f8f8 系）；**底部滚动余量保留 40vh**（不降基线 100px——文末不贴底体验，且为票 05 打字机模式留足滚动空间）。
4. **front matter 块**：保持灰底等宽预览块形态（§4.3 字节保留约束不动），颜色吃主题变量（#777 灰字系，基线规律 9）；**不做折叠交互**——超出排版范围、与字节保留约束有耦合风险，列为雾区候选增强。
5. **代码块视觉**：圆角 6px → **3px**；字号 0.9em；行号 `#999` 右对齐（基线 §5.3）；**新增语言标签**（代码块左上、砖红 `#b4654d` 系、吃主题变量）；代码块自动换行/行号两个设置项保留（confidant 特有）。⚠ 语言标签依赖引擎 codeBlock 节点 language 属性，实施时验证；engine 拿不到则降级为「仅主题化、不显示标签」。
6. **字体策略**：三主题西文字体分异——github/night 无衬线（**Open Sans**，SIL OFL）、newsprint 衬线（**PT Serif**，SIL OFL），字体文件从官方源（Google Fonts）引入打包，不复制 Typora 的字体资产；**中文正文/UI 显式声明微软雅黑体系**（比 Typora 的隐式系统回退可控）；代码字体链 `Consolas, 微软雅黑, monospace` 保留；源码模式等宽 UI 沿用。
