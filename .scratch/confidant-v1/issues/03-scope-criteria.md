# 范围裁决标准

Type: grilling
Status: resolved

## Question

把 Typora 候选能力判进/判出 v1 的裁决标准如何定义?本票产出的是「判定口径」本身(供后续逐主题仲裁票套用),不是对任何具体能力的裁决。

拟定回答的问题:判定维度有哪些(与核心写作体验的关联度、对目标画像的价值、与三原则——本地优先/所见即所得/大众可用——的兼容性、实现成本与风险口径、缺失时的损失严重度)?如何避免「Typora 有所以我也有」成为默认进的理由?裁决产出格式是什么(每项:进/出/延后 + 依据,延后=留给后续版本)?

前置(02 已决):用户画像已决出「画像 P1」(见 02 首版用户画像的 Answer)——本票产出的裁决标准须以 P1 为「对谁有用」的默认判据,不重复讨论画像。

## Answer

**决议:范围裁决标准**。适用范围:①三件套外的 Typora 候选能力(进/延后/出);②已进项内部的形态选择(如导出格式、图片存放策略)。三件套本身(文件树/WYSIWYG 编辑/导出)不进仲裁——已在范围内。

1. **机制:判据表(rubric),不搞数字打分。** 每项候选过以下维度,每维一句提示问句:
   - 与核心写作体验的关联:缺了它,P1 的周报/日记主流程是否明显受损?
   - 对 P1 的价值:对 P1 的 \<具体场景\> 是否有用(以 02 决议画像为准)?
   - 与三原则的兼容(相抵者见规则 4,自动出)。
   - 成本档:S/M/L 粗粒度(约 S=单包小改动,M=跨包新功能,L=需新技术验证),只用于排序与留档,不作实现承诺。
   结论规则:「进」方须给出正面论证(见规则 2),裁决 = 进 / 延后 / 出。
2. **默认出,举证进。** 每项候选默认不进首版;「Typora 有」四个字不得单独作为任何裁决的理由——只可作体验差异的对照参考,不可作论证。
3. **产出格式:统一裁决清单表留痕。** 规格附录一张总表:能力 | 类别(核心/增强) | 裁决(进/延后/出) | 成本档 | 依据(一句话,引用 P1 场景);进/延后/出全留痕,防决策丢失。「进」项另有正文章节详述。
4. **三原则冲突:一票否决,自动出。** 凡与三原则(本地优先、所见即所得、大众可用)相抵的候选不进入权衡,直接落「出」并注明抵触哪条原则——原则是承诺,不是可交易项。

裁决须以画像 P1(02 决议)为「对谁有用」的唯一判据;成本档证据不足时如实标注「待原型/研究补充」,不得用猜测冒充。
