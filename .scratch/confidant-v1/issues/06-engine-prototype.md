# 编辑引擎原型验证

Type: prototype
Status: resolved

## Question

按研究票结论(04 编辑引擎现状研究,调研见 docs/research/engine-survey.md)对推荐候选做**最小原型对照验证**:TipTap(首选)与 Milkdown(备选对照)。

验证目标不是「谁更好看」,而是回答选型决策(07 编辑引擎选型)需要的三个事实:

1. **源文往返保真**:打开一个本地 .md → 所见即所得编辑 → 序列化保存回 .md,源文被改动多少(重排、转义、CRLF/行尾处理、frontmatter 与非标准语法)。这直接喂「源文 1:1 保真是否成硬约束」的分岔(研究票已指出:若成硬约束,CM6 路线优先级反转)。
2. **关键能力粗验**:表格、图片(含粘贴)、中文 IME 输入时光标与组合行为(大众中文用户的关键体验)。
3. **集成与体感**:React + TS 类型体验、扩展点;首屏渲染与长文性能粗测(记录测量方法,不追求基准级精度)。

产出:可运行的对照原型(同一最小 Electron + React + TS 壳内两引擎切换即可)+ 一份对照记录(每条结论标注测试方法,跑不动或无法验证的如实标失败/未验证)。原型为讨论而造,**不入产品代码库**,不遵守 deep-module 布局约束;对照记录与关键代码作为本票资产链入决议。

本票只验证「候选站得住吗、各付什么代价」,**不裁决选谁**——那是 07 的裁决内容。

## Answer

**决议:两候选引擎站得住,语义级保真 6/6;字节级保真(源文 1:1)均不成立且不可配置关闭。** 详细对照与逐语料证据见 docs/research/engine-prototype-findings.md(原型代码按 prototype 惯例归档于分支 `prototype/engine-prototype-06`,不入主线)。

要点(实测 TipTap 3.31.3 / Milkdown 7.22.1):

1. 语义级往返:6/6 语料全过(TipTap 需显式注册 Image 扩展)。差异均在「同语义、不同写法」范围:CRLF→LF(TipTap 还丢文末换行;Milkdown 保留)、列表标记(`-` vs `*`)、分隔线风格(`---` vs `***`)、表格列宽衬垫与破折号归并、多余空行折叠、文首空行移除、硬换行写法(两空格式 vs 反斜杠式)。
2. 陷阱登记:TipTap 的 Image 不在 StarterKit——不注册则图片语法在解析期静默降级为纯 alt 文本(实测丢链接);实现必须显式列入并做「不支持语法不得静默丢内容」防御。TipTap 会把 HTML `<u>` 吸收为 Underline 节点、序列化改写为 `++…++`(渲染语义保留);Milkdown 对 HTML 原文透传。
3. 集成面:同为 ProseMirror 家族、MIT(04 研究核实);TipTap 官方 React 封装与类型成熟,Milkdown kit 可手动挂载、类型可用。
4. 性能(粗测,量级):重建式加载 7.4k 字符文档全程约 2s(开发机,非首开常态路径);逐键输入未测。
5. 未验(如实标注,已并入 07 选型会话补试):真 IME 组合过程、表格单元格编辑手感、任务勾选交互、渲染观感与长文滚动、图片粘贴落盘。

分岔移交:「源文保真取语义级还是字节级」由 07 编辑引擎选型裁决;若定字节级,两候选都不是现成答案,CM6 路线优先级反转(呼应 04 研究)。
