# 首版用户画像

Type: grilling
Status: resolved

## Question

「面向大众、无技术门槛」之下,首版规格里「面向谁」如何细分与落笔?规格需要哪些画像要素,才足以让后续所有仲裁与交互裁决都能问「对目标用户是否有价值」,而不是悬空讨论?

候选要素:使用场景(写日记/技术笔记/知识库/写作?)、文件组织习惯(单文件夹 vs 多项目分散)、对 Markdown 的熟悉度、迁移来源(Typora 前用户?Word?记事本?)、设备与平台习惯。

约束(证据纪律):仓库没有任何用户调研证据,不得虚构画像;若画像是「假设驱动」的,须显式标注假设性质与验证方式,避免写进规格时变成既定事实。

## Answer

**决议:首版规格以「画像 P1」为唯一核心用户假设,通篇显式标注假设属性。**

**画像 P1(全为假设,验证见下方检验清单):**

- 使用场景:工作与生活记录(周报、会议纪要、日记、清单、摘抄);不定期,每周至少几次。
- 写作体量:单篇几百字至两三千字;累计几十至几百个文件。
- 组织习惯:按主题建文件夹归档、树状管理;倾向先见全貌再决定写哪。
- Markdown 认知:不知道语法——WYSIWYG 是其写作不被打断的前提。
- 技术水位:会装软件、会用文件资源管理器;不碰命令行、不编辑配置文件。
- 迁移来源:Word/记事本/手机便签,无现成 md 库要导入(导入能力已划出范围)。
- 地域/语言:中国大陆,简体中文界面(单语言,不做 i18n——由 P1 地域假设推论,非硬范围承诺)。

**服务边界(仲裁规则式):** 大众可用 > 极客扩展。任何人可用但不为首版优化;凡与 P1 的大众可用冲突处,按 P1 赢。示例排除:高密知识库用户(双链/图谱/插件生态需求者)、多端同步需求者(已划出范围)。

**规格落笔格式:** 规格开篇一章「目标用户画像」放上表;此后每项进/出裁决的依据句统一句式——「对 P1 的 \<场景/习惯\> 是否有价值」。

**假设检验清单(执行时机:产品可用后;当前不执行、不建票):**

- P1 首开能否不引导即开始书写(WYSIWYG 前提是否成立);
- 是否出现「Markdown 是什么 / 我的文件在哪」类问题(认知与技术水位假设);
- 实际单篇与文件量级是否相符(量级假设);
- 简体中文单语言是否满足(地域假设)。

未验证前,规格与裁决一律把画像当假设引用,不得写成事实。
