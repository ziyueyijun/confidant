# 工作区与文件树形态

Type: grilling
Status: resolved

## Question

工作区与文件树的形态如何定?本票裁决的是「三件套之一」文件树侧栏的核心交互,以 Typora 为参照基线逐项确认:

- 工作区:单文件夹,还是支持多文件夹工作区(含切换/记忆)?打开方式(文件夹选择器、最近列表、欢迎页?)与 Typora 的差异?
- 树的表现:排序规则、缩进层级、展开/折叠记忆、超长文件名与重名的表现。
- 文件操作:新建/重命名/移动/删除(回收站?)的交互、与操作系统文件管理的边界(文件在外部被改/删除时树如何反应)。
- 边界情形:隐藏文件、符号链接、只读介质、空文件夹、非 .md 文件在树中的显示策略。
- 哪些细节留白给实现阶段、哪些必须锁进规格。

前置(02 已决):用户画像已决出「画像 P1」(见 02 首版用户画像的 Answer),其组织习惯假设(按主题建文件夹、树状归档、倾向先见全貌)是本票裁决的默认判据,不重复讨论画像。

## Answer

**决议:工作区与文件树形态**(三件套内形态裁决,适用 03 判据表;参照 Typora 仅作对照,依据一律引 P1)。

**进(首版锁定):**

1. 工作区 = 单文件夹:一次一个文件夹为根;「打开文件夹」即切换,保留最近打开列表(成本 S)。
2. 无标签页,单击树项即切换编辑区;同一时刻单文件在编辑(成本 S)。
3. 排序:同层文件夹在前、组内名称升序;展开/折叠状态记忆,重开还原(成本 S)。
4. 文件操作:树内右键菜单 + 快捷键(新建笔记/新建文件夹/重命名/删除);支持拖拽移动;删除单文件进系统回收站不弹确认;删除文件夹弹一次确认后进回收站;删除正在编辑的文件先提示(成本 M)。
5. 树显示:文件夹全显、文件仅 .md;隐藏文件与杂项不显;外部变更自动监听,原位即时反映(成本 M;含「正在编辑的文件被外部删除」的冲突提示原则,细则留实现)。
6. 入口:首启欢迎页(产品名 + 一句人话 + 「打开文件夹」主按钮 + 最近列表);常规态提供「打开文件夹 / 最近打开」入口;切换前不丢已编辑内容(成本 S)。
7. 侧栏形态:可收起(可见按钮,不依赖快捷键)、宽度可拖、当前编辑文件高亮并在不可见时自动展开定位(成本 S)。
8. 空态:空文件夹时编辑区显示一句引导(如何新建/放文件);文案措辞留规格写作(成本 S)。
9. 留白给实现:渲染细节(滚动/虚拟化/动画/图标风格)、重名提示、拖拽落点反馈。

**延后(记录在案,不消失):** 多根工作区;标签页多开;排序方式切换(名称/时间);多选批量文件操作;拖文件夹进窗口打开。

**出:** 侧栏常驻不可收(最小形态)——P1 写作需要全宽画布,无保留价值。

**规格正文承接:** 进项在规格中展开为交互描述(欢迎页结构、右键菜单项清单、空态文案等),本票只锁形态与原则。
