# 编辑引擎选型

Type: grilling
Status: resolved

## Question

在 06 编辑引擎原型验证的证据之上裁决:首版编辑引擎**选谁**(或是否需要补充第二轮验证)。

裁决输入:04 编辑引擎现状研究的候选池与能力矩阵 + 06 原型的对照记录。裁决判据:

- 「所见即所得」体验达成度:实时双向编辑、表格/图片编辑的体感;
- 「本地 .md 数据保真」承诺的落法:源文保真是否成硬约束(若成,研究已示 CM6 路线优先级反转)——这是本票最重的一个分岔;
- 中文 IME 输入体验;
- 许可证与维护面(全部候选 MIT,以 04 调研为准);
- 集成成本(React + TS + deep-module 边界下的可包裹性)。

产出:引擎定名 + 一句话理由 + 风险登记(选中方案的已知弱点与缓解),并为规格「编辑面深层交互」fog 的毕业钉下能力基线。

前置(06 已决):原型证据已入库(见 06 编辑引擎原型验证的 Answer 与 docs/research/engine-prototype-findings.md)——两候选语义级保真 6/6、字节级均不成立;TipTap 需显式注册 Image。06 的未验清单(真 IME、表格手感、渲染观感、长文滚动)并入本票会话补试:原型与 dev server 均在,先试后裁。本票裁决不再重复验证动作,以证据为准。

## Answer

**决议:首版编辑引擎 = TipTap**(实测 `@tiptap/*` 3.31.3,ProseMirror 基底;MIT)。

- **数据承诺口径(产品承诺,进规格)**:源文保真为**语义级**——文件始终是标准合法 .md,任何工具可打开、可带走、可备份;编辑保存时的格式化规范化(CRLF→LF、列表/表格风格、空行折叠、文末换行)属正常行为,不承诺字节不动。字节级保真不设硬约束(CM6 自研路线据此出局)。
- **能力基线(规格输入)**:标题、列表(任务列表)、引用、代码块、表格、图片(Image 必须显式注册)、链接、下划线等官方扩展支持;06 实测语义级往返 6/6。
- **风险登记**:
  1. Image 不在 StarterKit——实现必须显式注册,「不支持语法不得静默丢内容」写入实现验收;
  2. `@tiptap/markdown` 桥(2025-10 发布)较新——锁版本 + 升级回归测试;
  3. math 无官方扩展——08 编辑区仲裁若裁入数学公式须另行评估;
  4. 未验项(真 IME、表格手感、长文滚动、图片粘贴落盘)转实现首验清单,不入规格承诺。
- **规格正文承接**:编辑面条目以「TipTap + 语义级数据承诺」为约束;深层交互与导出管线 fog 随即毕业(见 13/14 票)。
