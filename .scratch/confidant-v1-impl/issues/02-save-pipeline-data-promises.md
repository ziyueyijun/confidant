# 02: 自动保存与写盘管线(数据承诺)

**What to build:** 规格第 4 节的数据承诺与第 9.3 节的保存模型在这里兑现。用户停顿约 1 秒后内容自动写盘,关闭窗口/切换工作区不存在「未保存内容」态;写盘原子化,崩溃最多丢最后一次防抖窗口内的键入;写盘规范化(CRLF→LF、列表/分隔线风格、空行折叠、文首空行移除、文末补单个换行——TipTap 序列化丢文末换行时补);front matter 块原样保留——打开→保存字节不变,显示为顶部等宽源码样式块,其余行为与普通文本一致;中文 IME 组合期间不触发保存;引擎不支持或降级处理的任何语法,打开→保存不得丢内容、不得静默降级(防静默丢失为验收级规则,违反即 bug)。

- 自动保存模型:编辑停顿(~1 秒)防抖后写盘;Ctrl+S 手动保存并存(Windows 肌肉记忆);关闭窗口/退出/切换工作区前对未落盘内容补一次保存(切换工作区的入口在 13/04,但保存侧行为本票立齐)。
- 原子写盘:先写临时文件再替换,写盘中断不留半截文件。
- 规范化仅作用于「差异项」:保存后文件始终是标准、合法的 Markdown;对列表标记/分隔线风格(`-`/`*`、`---`/`***`)、表格列宽衬垫与分隔线破折号、多余空行折叠、文首空行移除、CRLF→LF、文末单换行,字节不必不动,语义必须不丢。
- front matter:识别文件首部的 YAML 块,原样保留(不解析、不利用、不改写);渲染为文档顶部的等宽源码样式块,编辑区其余行为与普通文本一致。
- 防静默丢失验收矩阵:对能力基线全语法(标题 1–6、段落、粗体/斜体/删除线/下划线、链接、行内代码、代码块(围栏+语言)、引用、有序/无序列表、任务列表、表格、图片、分隔线、硬换行)与已知引擎不支持的语法(如数学公式文本 `$...$`、脚注等规格划出/延后项)各做「打开→保存」夹具,断言保存后内容语义不丢、不被降级成纯文本。
- IME:组合期间不触发保存/自动转换(jsdom 级 composition 事件门控 + 真 IME 人工项登记给 20)。
- 首验登记:front matter 补测场景(多行、中文、嵌套引号、无 front matter 的普通文档)归本票夹具。

**Blocked by:** 01(应用骨架与最小编辑闭环)。

**Status:** ready-for-agent

- [ ] 停顿 ~1 秒自动写盘;Crtl+S 立即写盘;两者写盘后磁盘文件与编辑器内容一致。
- [ ] 写盘原子:模拟写盘中断(测试层注入失败),磁盘不残留半截目标文件;崩溃(杀进程)后文件为上次完整保存内容,重开可恢复。
- [ ] 规范化矩阵夹具通过:CRLF 输入文件保存后为 LF;列表/分隔线风格、表格衬垫、多余空行、文首空行均按规则归一;保存文本以单个换行结尾;硬换行保存为行尾两空格、重开后仍为硬换行。
- [ ] front matter:打开→保存字节不变(多组夹具);编辑区顶部以等宽源码样式块呈现 front matter,其余文本行为与普通文本一致。
- [ ] 防静默丢失验收矩阵通过(能力基线 + 不支持语法场景),含 Image 显式注册防丢链用例。
