# 12: 外部删除与改名处置

**What to build:** 正在编辑的文件被外部(资源管理器/其他程序)删除或改名时,编辑区顶部出现提示条(规格 9.4,默认文案):「文件已被删除」+ 按钮「恢复重建」/「放弃」。**不静默重建文件**——用户主动删除不应被复活;误删/同步冲突可经「恢复重建」救回:在原路径重建文件并写回当前编辑器内容(救回键入)。「放弃」= 关闭该文件的编辑状态,树随磁盘状态刷新。外部修改(文件内容被外部改动)不弹窗打扰:以磁盘为最终真相(语义级承诺下的正常情形)——实现最小解释:编辑器无本地未保存输入时不弹窗重载为磁盘内容,避免静默覆盖外部改动;解释与边界记录在票尾。

- 依赖 04 的文件监听与 10 的删除/清空编辑区处理路径;「恢复重建」写盘走 02 管线(原子写)。
- 外部改名:新文件出现在树中,旧路径消失——按规格与删除同一处置(提示条),恢复重建 = 在旧路径重建;此处置选择记录在票尾。
- 本票不做「用户主动删除(树内删除)」的复活——那是 10 已裁决的语义(不静默重建只针对外部删除路径)。

**Blocked by:** 04(文件树侧栏基座——监听基础设施)、10(文件管理操作——删除/关闭编辑区处理路径与写盘语义)。

**Status:** ready-for-agent

- [x] 正在编辑的文件被外部删除 → 提示条「文件已被删除」出现(默认文案),不自动重建文件、不自动清空编辑内容;不做任何静默动作。
- [x] 「恢复重建」:原路径文件回来,内容 = 当前编辑器内容(编辑中键入不丢);重开后文件可继续编辑保存。
- [x] 「放弃」:编辑区退出该文件状态,树/磁盘一致,无残留保存动作指向已删除文件。
- [x] 正在编辑的文件被外部改名 → 同样出现提示条;恢复重建/放弃行为与删除一致,树中显示新名文件。
- [x] 文件内容被外部修改(路径未变):不弹窗打扰;无本地未保存输入时编辑区反映磁盘内容;实现解释与边界情形记录在票尾。
- [x] 树内删除(10 路径)不触发本票提示条(语义区分正确)。
