# 搜索体验与实现

Type: grilling
Status: open
Blocked by: —

## Question

全文搜索和快速跳转具体怎么工作？

这两个是「笔记软件」区别于「markdown 编辑器」的核心，已定在 MVP 内。要定的：

1. **两者是一个入口还是两个**：Ctrl+P 快速跳转文件名 vs 全文搜索内容。合成一个带前缀语法的浮层（VS Code 风格），还是分开？
2. **搜索范围与语法**：只搜正文，还是也搜文件名/路径？要不要大小写敏感开关、全词匹配、正则？**中文分词怎么办**——中文没有空格，子串匹配（`包含`）对中文其实够用，但要确认。
3. **索引还是现场扫**：几百到几千个文件的量级，现场 grep 可能就够了（实现简单、无一致性问题）。要不要索引取决于实测延迟。**需要事实**：这个量级下现场读盘搜索的实际耗时。如果决定要索引：索引存 `%APPDATA%`，何时重建，如何跟文件监听联动。
4. **结果呈现**：列表里显示什么（文件名 + 命中上下文片段？每个文件几条命中？）；键盘导航；点击后跳到命中位置并高亮；搜索面板和编辑区的空间关系（见界面布局原型）。
5. **当前文档内查找**（Ctrl+F）算不算 MVP？它和全文搜索是不同的交互。**注意**：在 WYSIWYG 下「查找高亮」怎么画是个实现问题，可能依赖内核能力。
6. **替换**要不要做？跨文件替换风险高（不可撤销地改一堆文件），倾向划出 MVP。
