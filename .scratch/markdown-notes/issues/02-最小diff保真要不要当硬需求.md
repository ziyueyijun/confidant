# 最小 diff 保真要不要当硬需求

Type: grilling
Status: open
Blocked by: 01

## Question

「我没碰的地方，一个字节都不许变」要不要列成硬需求？

**背景**：用户会**继续同时用 Typora 和 VS Code** 改同一批 .md 文件。笔记库不进 git，所以 diff 噪音本身不是问题，但**格式战争**是：若本软件在保存时做全文重新序列化（`*` 列表标记变 `-`、缩进宽度变化、软换行重排、强调符号规范化），而 Typora 又按自己的规范写回，同一个文件会在两套格式之间来回翻烙饼。

**要决定的**：

1. 硬需求（任何做全文重写的方案直接淘汰）、软偏好（能做到就做，做不到可接受），还是不在意？
2. 如果是硬需求，可接受的例外是什么？（例如：本软件自己插入的新内容用什么风格；用户主动触发的「格式化」命令是否算例外）
3. 「没碰的地方」的粒度怎么算——字节级、行级、还是块级？

**为什么 blocked by 内核与生态事实调研**：这个决定的代价取决于两条路线的真实能力差距。要带着「选 CodeMirror 路线能拿到字节级不变，选 ProseMirror 路线要放弃什么」这样的具体事实来问，而不是抽象地问用户在不在意。

这是整张地图里预期最关键的决定：它会直接约束内核选型。
