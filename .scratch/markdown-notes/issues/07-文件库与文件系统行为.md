# 文件库与文件系统行为

Type: grilling
Status: open
Blocked by: —

## Question

「库」这个概念的行为边界在哪，文件系统层面的各种意外怎么处理？

大方向已定（自动保存约 500ms 落盘 + 监听外部变更 + 无本地未存改动则静默重载 + 真冲突弹提示）。这张 ticket 把细节钉死。

1. **库的定义与生命周期**：一个库 = 一个文件夹。同时只能开一个库，还是可以多库切换？记住最近打开的库吗？库里的非 .md 文件（.txt、.pdf、图片）在文件树里显示吗？隐藏文件、`node_modules` 之类要不要过滤？
2. **CRUD**：新建笔记的默认文件名与位置；重命名文件时引用它的链接要不要跟着改（**注意**：scope 里没有双链，但相对路径的图片链接和文件间的普通 markdown 链接确实存在）；删除是进回收站还是直接删。
3. **外部变更的具体语义**：
   - 文件在外部被改、本地无未保存改动 → 静默重载。**但光标位置和滚动位置怎么保留？**
   - 文件在外部被删 / 重命名 / 整个文件夹被移走，而标签页还开着 → 怎么反应？
   - 真冲突（本地有未落盘改动 + 外部也变了）→ 提示长什么样，用户有哪些选项（保留我的 / 用外部的 / 另存一份）？
   - 云同步（OneDrive/坚果云）造成的高频抖动、临时文件、文件锁 → 要不要 debounce、要不要忽略特定文件名模式。
4. **自动保存的边界**：崩溃/断电时正在输入的内容丢多少可接受？要不要写临时文件再原子替换（避免写坏原文件）？只读文件、权限不足、磁盘满怎么反馈？
5. **大文件与异常文件**：遇到 50MB 的 .md、二进制伪装成 .md、非 UTF-8 编码怎么办。
