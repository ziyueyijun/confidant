# 可行性压测原型：IME 与表格

Type: prototype
Status: open
Blocked by: 03

## Question

选定的内核在最危险的三个点上，实测能不能扛住？

这是**风险退场（risk retirement）**原型，不是功能原型。目标是在写任何产品代码之前，用最小的 Electron + 内核 spike 把以下问题证伪或证实，用户亲自上手体验：

1. **中文 IME 压测**：长段中文连续输入、中英混排、输入过程中触发重渲染、在已渲染节点边界处输入、在表格单元格内输入、在代码块内输入。是否吞字 / 候选框跳位 / 光标错位。
2. **表格的 inline 编辑**：这是 Typora 类编辑器公认难点。建表、Tab 跳单元格、增删行列、单元格内换行、对齐语法的表达。
3. **长文档性能**：加载一篇万字（以及十万字作为极端值）文档，滚动、输入延迟、内存占用。
4. **落盘验证**：改动一处后 diff 实际长什么样——直接验证「最小 diff」结论是否真的成立。

**输出**：可运行的 spike（链接为 asset）+ 用户亲自试过之后的判断：这条路走得通，还是要退回「选定编辑器内核」重选。

如果这里发现内核不行，**回到内核选型 ticket 重开**，这是本地图里预期唯一可能回头的地方。
