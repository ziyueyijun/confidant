# markdown 规范化策略

Type: grilling
Status: open
Blocked by: 02, 03

## Question

本软件自己生成 markdown 时，用什么风格？不认识的东西怎么办？

「最小 diff」管的是**不碰用户已有内容**；这张 ticket 管的是**本软件新写出来的内容**长什么样，以及遇到边界情况如何不破坏文件。

要定的：

1. **风格选择**：无序列表用 `-` 还是 `*`；强调用 `*` 还是 `_`；标题用 ATX（`#`）还是 Setext（下划线）；代码块用围栏还是缩进；围栏用 ``` 还是 `~~~`；有序列表编号是 `1. 1. 1.` 还是递增。
2. **转义策略**：用户打出的字面 `*`、`_`、`` ` ``、`#`、`[` 什么时候该转义、什么时候不该。这是 WYSIWYG 编辑器最容易出错的地方（用户想打星号却变成了斜体，或者反过来）。
3. **不认识的语法怎么办**：文件里出现了原始 HTML、脚注、数学公式、mermaid、思源的块 ID 标记——这些都在 scope 之外。是原样保留当纯文本显示（**推荐方向**），还是渲染，还是报错？「原样保留不改写」应当是铁律，但**在编辑器里怎么显示**要定。
4. **行尾与编码**：CRLF vs LF（Windows 场景）、BOM、文件末尾换行。检测并沿用原文件的约定，还是统一？
5. **空白**：行尾两空格的硬换行怎么处理（它在 WYSIWYG 下不可见，极易被误删）。
