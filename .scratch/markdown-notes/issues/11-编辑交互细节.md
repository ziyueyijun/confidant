# 编辑交互细节

Type: grilling
Status: open
Blocked by: 03, 04

## Question

打字的时候具体发生什么？

内核选定、可行性验证之后，把编辑体验的交互规则钉死。这些细节决定「手感」，也是 Typora 让用户满意的地方。

1. **输入规则（input rules）**：打 `# ` 自动变标题、`- ` 变列表、`> ` 变引用、` ``` ` 变代码块、`**x**` 输入完自动变粗。哪些做，哪些不做？误触发怎么撤销（打了 `#` 但我真的想要井号）？
2. **语法标记的显隐规则**：这是 Typora 式效果的核心。光标进入节点时露出标记——「进入」的判定是什么？整个段落露还是只露当前节点？选区跨多个节点时呢？失焦时呢？
3. **快捷键**：加粗/斜体/代码/链接、标题层级升降、列表缩进（Tab/Shift+Tab）、移动行、Ctrl+P、Ctrl+F、新建/关闭标签页。跟 Typora 保持一致，还是跟 VS Code 一致？用户同时用这两个，冲突的地方要选边。
4. **粘贴**：从网页粘贴富文本 → 转成 markdown 还是纯文本？纯文本粘贴的快捷键。粘贴 URL 到选中文字上 → 自动变链接？
5. **Tab 键的含义**：在列表里是缩进，在表格里是跳单元格，在代码块里是插入制表符或空格，在正文里是什么？
6. **撤销**：撤销的粒度（一个字符、一个词、一次输入停顿）；自动变换（input rule）能不能一步撤销回源码形态。
7. **软换行与硬换行**：Enter 和 Shift+Enter 分别做什么，在列表里和在段落里是否不同。
