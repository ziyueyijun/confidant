# 地图：Windows 所见即所得 Markdown 笔记软件

Label: `wayfinder:map`

## Destination

一份可交接的实现规格（`.scratch/markdown-notes/spec.md`）：Windows + Electron 的 markdown 笔记软件，Typora 式真 inline 所见即所得，磁盘上永远是纯 .md 文件，库形态为「文件夹 + 文件树 + 标签页」。规格锁定技术栈、数据模型、WYSIWYG 渲染策略与 MVP 功能边界，交给实现 agent 后不需要再做设计决定。

产品命题一句话：**Typora 的编辑手感 + 类思源的库管理 + 磁盘上永远是纯 .md**。

## Notes

**域**：桌面应用 / 富文本编辑器内核 / markdown 解析与序列化。

**每次 session 应加载的技能**：`grilling` + `domain-modeling`（默认）；内核与生态事实用 `research`；「长什么样 / 怎么动」的问题用 `prototype`。

**已定的约束（grilling 已settle，不要重新讨论）**：

- 平台 Windows，壳用 **Electron**（用户明确指定）。
- 所见即所得 = **Typora 式真 inline**：单一编辑区，语法标记仅在光标进入节点时显露。不是双栏预览，不是富文本序列化。
- **文件为最小单位**，不是块。永远不会有块级引用——这是为了换取「文件干净、可移植」而明确接受的代价。
- 语法范围：**CommonMark + 表格 + 任务列表**。其余扩展一律不做。
- YAML frontmatter：**原样保留，绝不静默改写**；MVP 不做编辑 UI。
- 库级配置（窗口布局、标签页、索引）存 **`%APPDATA%`**，库目录保持绝对干净。
- 图片存**库根 `attachments/`，链接用相对路径**。
- 保存：**自动保存**（停止输入约 500ms 落盘）+ 监听外部变更。
- MVP 功能：全文搜索、快速跳转文件（Ctrl+P）、粘贴图片、暗色主题、代码块语法高亮（固定语言集，代码块内部永远纯文本编辑）。
- Windows 集成 MVP：单实例 + 接受命令行文件路径 + 安装时可选注册 .md 关联。
- 自用优先，MVP 不做签名与自动更新，但选型不得堵死发布路。

**一等验收标准**（贯穿所有 ticket，任何方案不满足即淘汰）：

1. **中文 IME 稳定性**：组合输入不吞字、候选框不跳位、光标不错位。用户中文为主、中英混排。
2. **磁盘纯净**：落盘结果是人类手写的那份 markdown，不是引擎吐出来的。
3. **规模**：几百到几千个文件，单篇通常几千字，偶有万字长文不卡。

**用户当前工具与痛点**（设计取舍的判据）：Typora（手感对，但闭源收费、不可扩展、库管理弱）、VS Code（本质是源码视图）、思源笔记（功能强但块结构 + 自有格式，笔记被锁在数据库里）。**用户会继续同时用 Typora 和 VS Code 改同一批文件**——任何一方做全文重写就会引发格式战争。笔记库**不进 git**。

## Not yet specified

- **长文档性能策略**：虚拟滚动 / 增量解析 / 视口外不渲染，具体做法取决于内核选型和原型压测结果。
- **测试策略**：WYSIWYG 编辑器怎么测。round-trip 属性测试（md → 模型 → md 是否等价）是核心，但可行性取决于内核。
- **打包与分发细节**：electron-builder 配置、免安装版 vs 安装包、体积优化。低风险，等主体决定后再说。
- **主题与配置界面**：暗色主题的具体实现（CSS 变量 / 内核主题接口）、字体设置、设置页形态。取决于 UI 原型。
- **首次启动体验**：没有库的时候界面是什么、怎么选库、要不要记住多个库。取决于「文件库与文件系统行为」的结论。
- **Frontmatter 的呈现方式**：原样保留已定，但「在编辑器里长什么样」还没定。取决于内核与 UI 原型。

## Out of scope

- 块级引用、双向链接、反向链接、关系图谱——与「文件为单位 + 纯原生语法」直接冲突，已明确接受这个代价。
- 大纲面板、导出 HTML/PDF、拼写检查、Vim 键位、多窗口——不影响核心架构，晚做无代价。
- 数学公式、脚注、mermaid、高亮标记等 CommonMark 之外的扩展（表格与任务列表除外）。
- 托盘常驻、全局快捷键唤出、最近文件跳转列表。
- 代码签名、自动更新通道、崩溃上报。
- macOS / Linux 跨平台。
- 云同步（依赖用户自己的 OneDrive/坚果云等外部同步，软件只负责正确处理外部变更）。
