# 同步状态存本机，不入库

同步锚点（「上次同步时远端长什么样」）与 WebDAV 凭据都存**系统 appData**，**不放库内 `.confidant/`**。

这是逆着「库自包含」这个直觉的选择——把配置放库内能让换台电脑时一切跟着走。但锚点**天然是每台机器独有的**：它记录的是「**这台机器**上次看到的远端是什么样」，放进库会同步给另一台机器，两台的锚点互相覆盖，逻辑上就是错的。凭据更严重——**把密码上传到它自己要连的那台服务器上，是逻辑上的循环**，而且「同步状态本身成为同步对象」这个递归问题会再次出现。

横向对比支持这一点：**七家参照产品（Obsidian Sync / remotely-save / Joplin / Syncthing / Dropbox / 坚果云 / Nextcloud）无一例外**把同步状态存在文件之外，且**一律不上传**到同步目标。

锚点的性质是「**可丢弃但不可重建**」——删掉它不丢内容（所以它不是真相），但会丢失归因能力（远端只有「当前长什么样」，没有「上次长什么样」），后果是**所有文件被判为冲突**。因此契约是：锚点丢失 → 强制保守全量对账、**绝不传播删除**。

代价：换电脑或重装要重新输一次 WebDAV 密码。对单人使用，代价基本为零。
