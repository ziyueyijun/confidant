# 笔记文件是唯一真相

笔记是用户自己的纯 Markdown 明文；**用任何外部编辑器改文件后，应用必须照常工作；索引必须能从文件完全重建**。这是本项目的最高原则——与它冲突的提案一律不作数。

这条不是默认选项，而是逆着行业主流的选择。有更好用户体验的产品几乎都走了另一边：Notion 纯云端、Apple Notes / Bear / Craft 是 SQLite、思源是 `.sy`（JSON）。最能说明代价的是 **Logseq 的 DB 版**——它把真相迁进 `db.sqlite`，结果 Markdown 导出变成**有损**（官方口径：`cannot capture all data in a graph`），唯一完整的导出格式是 EDN。**一旦索引升格为真相，可迁移性就不可逆地下降。**

## 放弃的东西

- **段落级块引用**：Obsidian 的块 ID 官方限定「只能由拉丁字母、数字、短横线组成」——中文做不了块 ID。本项目接受链接只到小节级。
- **CRDT 协作**（Yjs / Automerge）：与第一原则**根本冲突**。CRDT 的正确性依赖所有改动都经过它的运行时；用户用 Typora 改一次文件，CRDT 的文档树就与磁盘脱节，而 Yjs 官方文档**没有任何**「检测文件被外部修改并重新导入」的机制。
- **结构化数据库视图**：只能做到 Obsidian Bases 那种程度（视图定义存为独立文件，数据仍在 Markdown 里）。

## 代价与回报

代价是**应用不能把文件写坏**——没有数据库兜底，写坏就是数据丢失（因此有专门的写盘安全设计），且外部改动会带来断链等需要诚实呈现的状态。

回报是数据真正属于用户：能用 Git 做版本历史、能被任何工具处理、软件不做了也不丢东西。对「私人知识库」这个定位，这是立身之本。
