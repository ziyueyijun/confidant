# 检索用逐字索引，不用分词

中文检索的索引方式：**把每个汉字前后插空格后用 unicode61 建索引**（`科 学 家`），查询时以相邻字短语匹配等价于精确子串匹配。这推翻了本可预期的「用 jieba / Intl.Segmenter 预分词」方案。

实测（100 万字中文语料）：预分词方案的单字查询召回仅 **27%**、跨词子串 **31%**（搜「共和」丢 94%），且精度与召回不可兼得。逐字方案**全部类别 100% 召回 / 100% 精确**（783 个随机探针零假阴零假阳），索引 5.18×，查询 0.3–5ms。

关键的意外发现：`wangfenjin/simple` 那个看似复杂的 C++ 分词扩展，**本质就是逐字建 token（+拼音），不是词级分词**——所以能用一行纯 JS 正则复刻，**零依赖**。这也规避了整个行业的通病：**没有分词器，就没有「分词器参数固化在 schema 里、升级要重建索引」的问题**（思源每次改繁简/大小写都要重建索引，Joplin 干脆放弃 CJK）。全库 rebuild 仅 116ms，于是「必须做增量索引」的架构压力也消失了。

代价：索引体积 5.18×（100 万字约 14MB）；100% 精确**依赖查询后回查原文**（refine）消除标点造成的假阳——这带来一个必须处理的工程问题：FTS5 的 `snippet()`/`highlight()` 作用在插了空格的文本上，直接用它做高亮会返回「科 学 家」而不是「科学家」。
