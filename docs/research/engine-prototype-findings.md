# 编辑引擎原型验证对照记录(06 票)

- 日期:2026-09-06;环境:本机开发浏览器(Chromium,Vite dev),Node 24 / npm 11。
- 原型代码:`engine-prototype/`(throwaway,不入主线;验证完按 prototype 惯例入临时分支归档)。
- 版本快照:TipTap `@tiptap/*` 3.31.3(StarterKit + Table/TableRow/TableCell/TableHeader + TaskList/TaskItem + Image + 官方 `@tiptap/markdown`,`markedOptions:{gfm:true}`);Milkdown `@milkdown/kit` 7.22.1(commonmark + gfm preset)。
- 验证法:6 份语料(s1 中文日常/ s2 GFM 表格任务/ s3 CRLF 版 s1 / s4 图片链接/ s5 长文 ~7.4k 字符 / s6 边界)各走「打开 → 编辑器解析 → 序列化 → 与原文比较」。注入冒烟:光标处 execCommand insertText 中文长串后序列化(近似输入路径;真 IME 未验)。

## 逐项证据(两引擎)

| 语料 | TipTap 3.31 | Milkdown 7.22 |
| --- | --- | --- |
| s1 中文日常 | 语义一致;仅丢文末换行 | 语义一致;仅 `-`→`*`、`---`→`***`;文末换行保留 |
| s2 表格/任务 | 语义一致;表格列宽重排、分隔线破折号归并、表格前空行被折叠;任务列表语法保留 | 语义一致;表格列宽重排、分隔线破折号归并;表格结构空行保留 |
| s3 CRLF | CRLF→LF 全量重写 | CRLF→LF 全量重写 |
| s4 图片链接 | 语义一致(须显式注册 Image 扩展,见「陷阱」) | 语义一致,原样保留 |
| s5 长文 | 语义一致;丢文末换行;多余空行折叠 | 语义一致;空行折叠;`-`→`*` |
| s6 边界 | 文首空行移除;行尾空格硬换行保留(两空格式);HTML `<u>` 解析成 Underline 节点、序列化为 `++下划线?++` | 文首空行移除;硬换行序列化为行尾反斜杠式(`  `→`\`);HTML 原文透传保留 |

## 结论性事实

1. **语义级保真:两引擎在全部 6 份语料上都成立**(差异均在「同一语义、不同写法」的规范范围内)。「打开能看、改完不丢内容」两候选都合格。
2. **字节级保真:两引擎都不成立,且不可配置关闭**:序列化是规范化过程——CRLF→LF(Windows 现实相关)、列表标记与分隔线风格、表格衬垫、空行折叠、文末换行(TipTap 丢 / Milkdown 留)。结论:若「源文 1:1 不重排」作为硬约束,两候选都不是现成答案(与研究票 04 的 CM6 路线分岔呼应)。
3. **陷阱(实现时必须处理,非引擎缺陷)**:
   - TipTap:**Image 节点不在 StarterKit**。不注册 `@tiptap/extension-image` 时,图片语法在解析期被静默降级成纯 alt 文本(链接丢失)——实测注册前 s4 输出只剩「窗帘样品」。注册后往返正常。任何基于 TipTap 的实现必须把 Image 显式列入扩展白名单,并做「不支持语法不得静默丢内容」的防御。
   - TipTap:HTML 片段会按语义节点吸收(`<u>`→Underline→`++…++`),源文写法被改写(渲染语义保留)。
   - Milkdown:硬换行写回反斜杠式;`-` 全部改 `*`——纯 md 手写党观感差异大(对 P1 无感,渲染一致)。
4. **集成面**:两引擎同为 ProseMirror 家族、MIT(04 研究核实);React+TS 集成 TipTap 官方 React 封装成熟,Milkdown 为框架无关插件式(React 用自管生命周期亦可,本次即手动挂载)。TS 类型:TipTap 官方包类型完整;Milkdown kit 类型可用。
5. **性能(粗测,仅量级)**:重建式加载(销毁+重建编辑器)7.4k 字符文档全程约 2s(开发机,含框架重建与 React 渲染,非首开常态路径);逐键输入性能**未测**(需人工真机)。
